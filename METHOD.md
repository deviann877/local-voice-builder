# Local voice-update method and limits

The research method demonstrated a local stock-package transfer and then modified spoken audio through a compatible L60 speaker. This distribution does not include the research device identity, account data, firmware/build identifiers, personal captures or any audio. It makes no claim to first discovery.

The implemented request uses Tuya local protocol 3.3, CONTROL and data point 162. Its value is base64 of a varint-length-prefixed protobuf message. Outer field 1 contains a descriptor and outer field 2 is an empty length-delimited selection. Descriptor fields are: 1 package ID (varint), 2 download URL (string), 3 archive MD5 (string), 4 version (varint), 5 archive byte count (varint). These fields reproduce the reviewed observed mechanism; they are not a manufacturer-supported API. MD5 is a checksum, not a signature.

The reviewed status representation is also length-prefixed and base64 encoded. Scalar fields 2/3 identify current package/version, 4 identifies the target and 5 reports state. State 2 was observed with settled success and state 3 with failure; missing/unrecognized responses do not establish success. Field 1 is deliberately not used for installation decisions. A complete observed GET and matching settled response are required for the strongest success message. Actual changed audio and normal operation still require the owner's check.

Only English package IDs 501 and 502 with matching female/male folders, unchanged configuration and the reviewed 86 filenames are accepted. This structural gate does not establish compatibility for every L60 or firmware. Firmware/model are not independently read by this program. The owner must confirm the target and decide whether to use this experimental mechanism. Other package families are refused.

The software sends at most one query and one control frame per installation connection. Automatic protocol detection and retries are disabled, with an additional frame guard. The temporary HTTP listener binds only the local route interface, serves one in-memory archive under an unguessable path to the target source address and closes after the observation. A different LAN host can potentially spoof a source address; use a trusted network. No credentials are placed in the URL. No router/firewall changes occur.

Stock restoration through official language selection was observed after completed updates in research. Recovery after rejection, interruption or power loss remains unproven. Persistence, long-term behavior and compatibility across releases require further validation. The new GUI has synthetic/software validation only; no new physical-device test is implied.

Implementation context: [TinyTuya](https://github.com/jasonacox/tinytuya), [community Robovac integration](https://github.com/Ascendor/robovac-l60-hybrid), and [community voice-update tooling](https://github.com/clutchthrower/Eufy-L50-Custom-Voice). Related-model findings alone are not compatibility evidence. Event labels are community interpretations, not a complete device-validated trigger catalogue.
